Acerca de FIERN

Framework Inteligente para la Extracción de Reglas de Negocio.

Volver

Qué es FIERN

FIERN (Framework Inteligente para la Extracción de Reglas de Negocio) es la aplicación que utiliza el equipo funcional para transformar programas COBOL heredados en documentación de reglas de negocio clara, trazable y revisable.

El problema que resuelve: el conocimiento de negocio de muchos sistemas críticos solo existe hoy dentro del código COBOL, disperso y difícil de interpretar para quien no programa. FIERN localiza los fragmentos de código con relevancia funcional real (validaciones, códigos de retorno, transiciones de estado, cálculos) y redacta un borrador de regla de negocio para cada uno, siempre con referencias exactas a la evidencia técnica que la sustenta.

Qué se sube a FIERN

Un paquete Altamira: un archivo .zip con la estructura estándar acordada (código fuente COBOL, y opcionalmente definiciones de tablas paramétricas). El tamaño máximo permitido se indica en la pantalla de subida.

Cómo funciona, en líneas generales

  1. El analista sube un paquete Altamira desde Nueva ejecución.
  2. FIERN valida y analiza el código, y construye un modelo del programa y sus dependencias.
  3. Detecta automáticamente los candidatos a regla de negocio.
  4. Para cada candidato arma un contexto completo: dónde está en el código, qué datos usa, qué tablas paramétricas aplican, qué efectos produce.
  5. Si hay un proveedor de enriquecimiento configurado, redacta un borrador de regla en lenguaje funcional para cada candidato.
  6. El analista revisa el resultado desde el detalle de la ejecución y descarga las reglas finales.

Cada subida se procesa como una ejecución (también llamada job) independiente, visible en Ejecuciones, con su propio progreso y su propio resultado.

Las fases del análisis, explicadas funcionalmente

Recepción y validación
El paquete se recibe, se verifica su integridad y su estructura.
Extracción e inventario
Se desempaqueta y se cataloga cada programa y archivo incluido.
Análisis del código
Se interpreta la estructura real de cada programa COBOL.
Dependencias y enriquecimiento semántico
Se identifican relaciones entre programas y se asocia significado de negocio a los datos relevantes (por ejemplo, qué campo representa un código de retorno).
Modelo de conocimiento
Toda esta información se organiza en un modelo consultable que sostiene el resto del análisis.
Detección de candidatos
Se identifican los puntos del código con relevancia funcional demostrable.
Construcción de contexto
Se reúne toda la evidencia necesaria para redactar cada candidato con precisión.
Redacción y validación de reglas
Se genera el borrador funcional de cada regla y se verifica que toda afirmación tenga evidencia real que la respalde.

Qué es un candidato

Un candidato es un patrón del código que FIERN identificó como estructuralmente relevante para una posible regla de negocio (por ejemplo, una condición que determina un código de retorno, o un cambio de estado). Un candidato es un hallazgo, nunca todavía una regla confirmada: recorre el resto del análisis antes de convertirse en un borrador revisable.

Qué es el "contexto" de un candidato

El contexto (también llamado ContextPackage) es el expediente completo de un candidato: en qué programa y línea aparece, qué condición evalúa, qué tablas paramétricas influyen, qué efecto produce (por ejemplo, qué código de retorno asigna) y qué evidencia técnica respalda cada uno de esos hechos. Es la única información que se usa para redactar el borrador de regla: nunca se afirma nada que no esté respaldado por el contexto.

Enriquecimiento con inteligencia artificial

Con un proveedor configurado: FIERN redacta automáticamente un borrador de regla en lenguaje funcional para cada candidato, a partir exclusivamente de su contexto, y aplica una verificación automática que rechaza cualquier afirmación sin evidencia.

Sin un proveedor configurado: la ejecución se detiene antes de esa etapa. Los candidatos y su contexto completo quedan disponibles igualmente para revisión manual, pero no se genera el borrador redactado automáticamente.

Qué puede consultar el analista

  • La lista de candidatos detectados en cada ejecución.
  • El contexto completo de cada candidato.
  • El borrador de regla propuesto y su verificación de evidencia, cuando el enriquecimiento está disponible.
  • El paquete final de reglas, descargable una vez completada la ejecución.

Qué significa el estado de una ejecución

En ejecución
FIERN está procesando el paquete en este momento.
Completado
El análisis terminó con éxito y las reglas están disponibles.
Fallido
El análisis se detuvo en algún punto; el detalle de la ejecución indica en qué fase y por qué. Puede reanudarse.
Ya procesado
El paquete subido (identificado por su huella digital exacta, no por el nombre del archivo) ya había sido procesado antes; se muestra la ejecución original en lugar de repetir el análisis completo.

Cómo se identifica un paquete ya procesado

FIERN calcula una huella digital criptográfica (SHA-256) del contenido exacto de cada paquete subido. Dos archivos con el mismo nombre pero contenido distinto son paquetes diferentes; el mismo contenido subido con otro nombre de archivo es el mismo paquete. Si un paquete con la huella exacta ya tiene una ejecución existente (en curso, completada o fallida), FIERN no vuelve a procesarlo desde cero: muestra una referencia a la ejecución original.

Qué hace "Limpiar job"

Elimina de forma permanente todo el rastro de una ejecución: sus resultados, sus artefactos y los datos que haya cargado en el modelo de conocimiento. Esta acción requiere confirmación explícita y no puede aplicarse a una ejecución que está en curso.

Una vez limpiado el job, el mismo paquete (mismos bytes exactos) puede volver a subirse y ser procesado como si nunca se hubiera analizado antes.

Precauciones importantes

  • "Limpiar job" es una acción permanente: no hay forma de deshacerla desde la aplicación.
  • Un borrador de regla es siempre material de revisión funcional, nunca una regla oficialmente aprobada por sí sola.
  • Verifique siempre la evidencia citada antes de dar por válida una regla propuesta.
